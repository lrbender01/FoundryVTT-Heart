# Changelog

All notable changes to this **personal fork** of `hitcherland/FoundryVTT-Heart` will be documented here. Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versioning continues upstream's numbers. The first fork release carried a fork-identifying suffix (`0.10.5-pr94`); from `0.11.0` on, versions are plain numbers.

**This is a personal v12 maintenance fork.** Upstream (`hitcherland/FoundryVTT-Heart`) is frozen at `0.10.4` (Sep 2024) on `main`; the maintainer pivoted to v13 development on the `new-magic` branch. This fork carries community contributions and bug fixes the upstream `main` will not receive.

See [CLAUDE.md](CLAUDE.md) for fork rationale, build pipeline, and known issues.

## [Unreleased]

Becomes 0.11.1.

### Fixed

- The built `heart.js` threw `ReferenceError: module is not defined` at load since the package became ES-module: `src/index.js` tested a bare `module.hot`, which strict-ESM webpack leaves undefined. It now tests `import.meta.webpackHot` (always undefined outside a dev server, so the block stays dead code, as before).

### Changed

- The package is now ES-module (`"type": "module"`), so Node tools that import the fork's `src/` no longer print a typeless-package warning. The CommonJS build files (`webpack.config`, `foundryvtt.config`, and everything in `dev-utils/`) are renamed to `.cjs`, and every build script passes `--config webpack.config.cjs`. No change to the built system.
- The Heart Map's toolbar (the board's rail, its File menu tiles, and the group fold-outs) drops the glass for Foundry's own scene-control style: each button a 5px-radius box on a half-black fill with a black border, a soft black shadow, and the pale control text; hover and the active tool take Foundry's bright text, red-and-orange border, and orange glow. No panel or blur behind the rail, in either direction. Every window it opens stays glass. New fixed colour roles `--heart-ctl-*` in `theme.sass`.

### Added

- **The board's parts, described once (ecosystem audit, 2026-10-27).** `BOARD_PARTS` in `scrapboard/model.js` is the one description of the board's top-level parts (scraps, links, pins, marks, bits, decor, bin, pinsEd, notesEd, sheet, pieces, and stages): each part's kind, its empty value, whether it is always there, whether the view carries it, its depth for updates, and whether its records are whole things. `PART_NAMES`, `unknownParts`, and the lists in `boardfile.js` (a loader per part, checked when the module loads) and `api.js` (export, replace, and copy) now derive from it, where they were hand-kept in ten places and had dropped data twice (the pins' edition on 2026-10-21; pieces and stages on 2026-10-27). `boardFromText` reports a key the description does not name in `unknown` and leaves it out of the board it returns; `boardParts` carries it through untouched, so a newer editor's board loses nothing in an older one. New `test/scrapboard-parts.test.mjs` carries a board with every part populated through each path that reads or writes a board and fails when one is dropped.
- **A named entry point for the board's pure files (ecosystem audit, 2026-10-27).** `src/map/scrapboard/index.js` re-exports the twelve files that load in plain Node with no Foundry, PIXI, or DOM global (`model`, `hits`, `controls`, `paint`, `richtext`, `changes`, `baked`, `boardfile`, `roofRule`, `actorTools`, `railGroups`, `live`) and lists them as `PURE_FILES`, so Map Dreamer, the content tools, and the Plenty checks import one path instead of deep file paths. `test/scrapboard-pure.test.mjs` imports every one with the globals absent. The root `eslint.config.mjs` restricts those globals in ten of the files (not `paint.js` or `richtext.js`, which use `document` as a default argument), and `package.json` has an `exports` block (not opened further); there is no `"type": "module"` line.
- **Groups other modules add to the board's rail (Luke, 2026-10-27: Heart Board Tools leaves its macro for the board's controls).** `game.heart.board.railGroups.register({ id, icon, title, gmOnly, fold, tools: [{ name, icon, title, label, run, on }] })` draws a group on the rail after Session scripting, in the rail's glass, in both layouts (`scrapboard/rail-groups.js`, the pure registry, tested; `rail.js`). `fold` puts the tools under one button that opens a sub-rail of tiles beside it, as File does. A GM group's tools are never run for a player. Foundry's own column gets a matching control when the board's toolbar is off. `game.heart.board.windows` hands a module the board's floating windows (`floating`, `kept`, `writeWindow`, `shutButton`, `registerToolWindow`, `carry`), so its windows are dragged, sized, remembered, and put back by the toolbar like the board's own.
- **Actor tools on the board's rail (Plenty finish item 1a, 2026-10-26).** The rail shows on a board scene while either the board's control or Foundry's token control is in hand, and carries an Actors group first: Select (click, box-select, drag, turn with the wheel), Measure, and Target, Foundry's own token tools. A board tool pressed from there goes back to the board. **Q** (a keybinding, everyone's, never while typing) flips between the board tool last held and token Select, for players moving their familiars too. Rail buttons (Undo, toggles, File) no longer pull you off the token tools, and keep the board tool in hand when they rebuild the board's control. Foundry's token tools panel is hidden on board scenes while the rail is on. The rail now runs along the top by default (a client that turned it keeps theirs). Pure parts in `scrapboard/actor-tools.js`, tested. Known: a scene redraw (a Sheet size change, an Undo that resizes) puts the board's control back in hand.
- **GM notes (Plenty finish item 2, 2026-10-26).** A card, pin, or string can be the GM's for good: `state: 'hidden'` plus `gm: true`, so any client or tool that doesn't know `gm` still sees a hidden ghost. The GM sees GM notes in full, not as ghosts (look `'gm'`); players never get them; Reveal leaves them alone (`revealPatch`, `controls.js`). The note window has a **GM note** switch for the GM. The rail's **GM notes** button (and a line in File, Map layers) shows or hides them on this client only (`boardGmNotes`, render-only: `model.js` `withoutGmNotes`). Like hidden notes, they live in the scene's flags, so a player at the console could read them. Tested in `test/scrapboard-gm-notes.test.mjs`.

### Fixed

- **A dark rectangle flashing as a bare board zoomed out (Luke, 2026-10-26, the witch's hut).** The board's own tiles came back under the sharp ones before those were replaced, for a moment both see-through layers showed. Now on a bare board only one shows: the sharp ones while they cover the whole view, else the board's own alone.
- **A bare board's colours darker zoomed in (Luke, 2026-10-26: "my color gets lighter when I zoom out").** The sharp tiles laid over the view when zoomed in left the board's own tiles under them; on a board with no sheet (a scene's background, or a baked map) both are see-through, so every stroke in view showed twice. The board's own are hidden while the sharp ones cover the view, and shown again the moment a pan passes them (`render.js` `syncBase`).
- **A board's tidy wrote back over strokes laid while it waited (2026-10-26).** Opening a board starts its tidy, which read the board, waited on the look, and wrote its copy back: the Plenty sketch's strokes, laid in between, were wiped. The tidy, and the Board tab's sheet changes, now make their board when the write's turn comes (`api.js` `replaceBoard` takes a function); `game.heart.board.patch` writes a patch in the board's own turn, for macros.
- **A bare board's empty tiles held memory (2026-10-26).** A 25,000 px board with nothing drawn on most of it held about 400 MB of empty tile canvases; a tile nothing reaches is now never painted and let go (`changes.js` `anyMeets`).
- **One eraser drag across many strokes lost their far sides (Luke, 2026-10-25: the gate doodle's bars lost their lower halves).** Each stroke's extra pieces were given new ids from the board as it was, never counting the ids already given out in the same drag, so every stroke's second piece took the same id and only the last one's survived. Ids are now counted across the whole drag (`model.js` `cutPatch`). The same mistake, latent, in a card brought back from the bin: a pin given a new id could take the id of the card's own pin still to come back, one overwriting the other (`unbinPatch`).
- **A player's doodle laid quickly overwrote strokes already there (2026-10-25, a sweep for the gate's bug class).** The player picked the doodle's stroke ids from their own board, which can be behind the GM's: a second doodle laid before the first came back took the first's ids and replaced it, and on a card one could replace another's stroke under that user's name. The player now sends what was laid; the GM works out its strokes and ids (`notes.js` board.edit `doodle`, as the eraser's `cut`).
- **Two quick pins, strokes, doodles, cards, or strings on the GM's own client made one (2026-10-25).** Their ids were picked before the write before them had landed. A queued write now picks its ids when its turn comes, from the board as it is then (`api.js` `update` and `applyBoardPatch` take a function; `model.js` `freshStrokeIds`), the relay's card strokes, doodles, and cuts too.
- **A note and a stroke on it made public together: the stroke stayed private (2026-10-25).** The note's switch replaced the stroke's in the same patch (`model.js` `sharePatch`). A stroke named twice in an eraser request is cut once (`cutPatch`).
- **An eraser grazing a stroke never showed until something else repainted there (Luke, 2026-10-25).** The sheet's change check left out a stroke's bites, stretch, and seed; a graze bites a stroke without moving a point (`paint.js` `markState`).
- **The eraser cuts and bites accurately, every nib (Luke, 2026-10-25).** A cut kept only the six eraser circles nearest each cut end (and a stroke at most 24 bites), so a broad stroke stayed joined across the cut; every circle of the eraser's that touches a piece's ink is now its bite (up to 600). A stroke is cut through only where the eraser covered its ink's whole width; where it only touched the ink (an edge, a graze, a narrow eraser down a broad stroke) the stroke stays whole and is bitten, where before a graze off its middle did nothing. A cut end runs on no further than the eraser's radius, and a wash's cut end is square. A stub the eraser never touched is kept, never dropped as a sliver. A piece's dry brush gaps now line up with the whole stroke's (a variable of the same name hid the piece's start). The last few px of a drag are rubbed out too. A filled wash is bitten where the eraser touches it and goes only when the eraser covers all of it (Whole strokes still takes it in one touch). `model.js` `cutStroke`, `paint.js` `brushLayer`.
- **A moved pen or wash became a brush stroke (Luke, 2026-10-25).** Moving, sizing, or turning a selected stroke dropped its nib and fill (`controls.js` `#strokesPatch`).
- **The previews that follow the pointer, the root cause (Luke, 2026-10-25, the tech session).** The layer heard the pointer through a listener on `canvas.stage`; each time Foundry draws a scene it activates the layer last in hand, then clears every listener on the stage, so after any scene draw the doodle's ghost, the eraser's ring, the reticle, and the hover outline were gone until the layer was put down and taken up again. The layer now hears the pointer on itself (`globalpointermove`). The guard ending a drag on a move with no button no longer reacts to the moves Foundry makes up itself, which had cut strokes short when a token moved or the view panned.
- **A stroke flashed off and on as it ended (Luke, 2026-10-25).** Its preview was hidden at once, and the board showed the stroke only once the scene's update came back and was painted. The preview is now held until a painted board shows the stroke (by its place and points), or 4 s; a doodle laid is held the same way.
- **A stroke drawing slowly (Luke, 2026-10-25).** Each redraw of the marks painted the stroke whole twice and sent both pictures to the GPU; it is now painted once per new point, one picture shown three ways (the laid-on pass tinted by the grime's veil).
- **The board's first paint and every repaint after a stroke (Luke, 2026-10-25).** The sheet's sharpened prints were read back from the GPU (seconds of a long stroke, in a profile); the canvases read back are CPU-backed now (`paint.js` `readBack2d`).
- **The eraser and the hover outline on a busy board (Luke, 2026-10-25).** Every pointer move and eraser step measured every point of every stroke; each stroke's box is checked first, and the stroke list is kept per view. The eraser's tint is one canvas the size of the view, kept, never one the size of its whole path made each move.
